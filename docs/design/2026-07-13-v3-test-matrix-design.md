# v3 全量测试矩阵设计:找字幕工作流(野心=替代 Bazarr)

日期:2026-07-13。状态:设计中(brainstorming,用户已逐问拍板)。
前置:首次真站验收通过(进击的巨人 S01E01 从 Moozzi2 合集包 installed,挖穿三层根因)。

## 目标与哲学

**野心**:替代 Bazarr。Bazarr 的死法=一集找不到单集字幕就报缺失,明明有整季/合集包却不会用。v3 靠 agent 智能judgment 破这个死局。

**测试哲学(用户定,铁律)**:
- **暴露问题=好事**。只要能诊断根因并解决,就是 auto-research 的养料。一千多离线测试只是开始。
- **离线全绿≠真能用**。刚才三层根因(Output.object 毒/参数流三连)离线 1263 测试全测不出,只有真 LLM 暴露。**真模型是暴露 bug 的唯一有效手段,测试矩阵必须保留它。**
- **NAS 素材贫瘠且不重要**——它们只是测试素材,真要测就删光字幕做全量 live test。本轮矩阵在**本地 OrbStack 容器**跑。

## 分层(A→B→C,三层最终都要跑通,分层推进不纠缠)

- **A 层·找字幕子代理**(本轮先做):worker 拿到"找这个目标",面对真实源返回的各种形态×各种资源类型,能否判断对/定位对/装对。刚才真站验收=A 层的一个格子。
- **B 层·主代理编排**:读活文档→正确判断"缺哪些集"(缺一集/整季/1到大结局全集/每季缺几集/有些季全缺有些缺一两集)→派出正确粒度的任务。**"缺什么"维度属于 B 层,不是 A 层。**
- **C 层·端到端**:dashboard 全仓校验→主代理判断缺口+派活→子代理找装,全链条在各种组合下跑。

## A 层矩阵(本轮实施)

### 真实度策略(A3:三档)
- **密集层(A2)**:OrbStack 容器里,**真 mimo-v2.5 + 录制的 assrt/OS 响应**跑每个格子。真模型保留(暴露 bug 关键),录制响应免 rate-limit、可重复、进回归集。
- **锚点层(A1)**:每种资源类型挑 1 格用**全真**(真 provider 真下载)跑,验证录制夹具没失真;顺手录真实响应进夹具库。
- 配额现实(用户澄清):**assrt 无日配额,仅 5 次/分钟 rate limit**(限速即可无限录);**OS 100/天仅"下载"消耗,搜索/查询 API 免费**;真模型走公司 API 无配额忧虑(只慢+烧 token)。→ 素材大方录,只需限速 + 珍惜 OS 下载次数。

### 每格断言
- finalize=installed?装的是**对的那一集/那个版本**?语言标对(zh-Hans/zh-Hant)?沙盒没越界?无异常抛出?步数合理(观测记录,不设硬顶——用户"测试期不设步数上限先观测")。
- **反例格(必含)**:确实没有对的字幕时,worker 诚实 finalize=no_safe_match,不瞎装。这是"不比 Bazarr 更烂"的底线——Bazarr 至少不装错,我们不能为了"有结果"装错。

### 素材与录制
- 先盘现有 assrt 缓存(23 个响应,日漫类形态齐)→ 直接建日漫行夹具。
- 缺的资源类型(国产/欧美/电影)+ 缺的形态,限速内补录真实 assrt/OS 响应。
- 录制存 `fixtures/v3-live/<资源类型>/<形态>/`,成为**永久回归资产 + auto-research 回归集**。
- 每格附"预期正确答案"(哪个候选/哪个 fileIndex 是对的)供断言。

### 暴露问题的处置(auto-research 闭环)
每格跑出问题→systematic-debugging 挖根因→判定是"认知缺口(改 skill,人 curator)"还是"技术 bug(改代码)"→沉淀(代码修复+真实化 mock+事故日志)→回归集复跑(绕过负缓存)。**skill 只由人+主控 Claude 改,agent 无权自改(铁律)。**

## B 层矩阵(A 跑穿后)
主代理编排的缺口判断+派活粒度:缺一集/缺整季/缺 1 到大结局全集/每季缺几集/有些季全缺有些缺一两集。断言:主代理读活文档后判断的缺口=真实缺口;派出的 worker_task 粒度对(不漏派/不重派/幂等);合集包场景下派活意图正确(一个覆盖一季的任务,而非 25 个单集任务)。

## C 层矩阵(A+B 跑穿后)
端到端:dashboard 全仓校验→机械预清洗→主代理→子代理→装上。在"缺什么×什么资源×源返回什么"组合下跑,含间谍过家家实弹(整理子代理+找字幕子代理协同)、正常库零误触发硬门。
