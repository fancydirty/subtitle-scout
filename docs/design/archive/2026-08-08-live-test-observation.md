## 🔴 发现一个既有债务：稳态下 orchestrator 不被触发

### 现象

开跑后约 15 分钟，管线自行停滞。日志：

```
[watch 02:10:01] ingest: scanned=492 upserted=0 parked=0 removed=0 orchestratorTriggered=false
```

`parked=0` 指的是**本轮新增** 0 条（441 行是既有的）。因为没有变化，
`result.changed=false` → orchestrator 不入队 → 没人派新的识别/找字幕任务。

### 根因（代码自陈的债务）

`src/daemon/ingestTrigger.ts:64` 只在 `result.changed` 时触发 orchestrator。
`src/v2/daemon.ts:11` 有个兜底心跳，但间隔是 **24 小时**：

```ts
export const ORCHESTRATE_HEARTBEAT_MS = 24 * 3_600_000
```

该文件注释自称"债务D2"，并写明这个洞的形状：
> 无变化世界里 ingest 恒 changed=0、永不触发 orchestrate ——
> "识别晚到/pending 屏蔽"类惰性收敛洞永不愈合

**这不是本轮改动引入的**，是既有设计。但它让"441 个 parked 路径 + 69 集缺字幕"的收敛
要等 24 小时一拍。

### 我做的临时处理

手动触发一次 `POST /api/v2/reconcile-all`（既有入口，不改代码）。它立刻派了 4 个任务：

```
dispatchedFindSubtitle: 4
(1) 441 个 parked 文件的识别 backlog — revived
(2) Nukitashi the Animation S1（11 集缺字幕，磁盘 11 = TMDB 11）
(3) Gachiakuta ...
(4) ...
```

管线随即恢复，之后 20 分钟里产出了上表那 52 条字幕。**这也顺带验证了方案 §6 的论证**
（识别落库 → `sub_status='missing'` → orchestrator 的 `list_missing_coverage` 看得到 →
派 per-series 找字幕任务）——那条链真的通。

### 需要你裁决

三个选项：

1. **把心跳从 24h 改短**（比如 15 分钟）。一行常量改动，但要想清"空转的 orchestrator pass
   烧多少 token"——每次 pass 是一次 LLM 调用
2. **改触发条件**：不只看 `result.changed`，也看"库里是否还有 parked 行 / 缺字幕的集"。
   更精准但要动 `ingestTrigger` 的判据
3. **不改**，靠 dashboard 上的"全仓校验"按钮手动推 —— 但那违背"用户只看不动"的产品目标

我倾向 **2**，因为它符合"有活就干、没活就歇"的语义，不会空转烧 token。但这是新设计，
要走一遍你定的流程（第一性原理 → 方案 → 对抗审计 → 计划 → subagent 实现）。
