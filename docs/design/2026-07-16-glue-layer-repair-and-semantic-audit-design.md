## 第〇部分 · 反省（成因分析，写给所有后续 session）

**事故**：v3 主子代理架构的胶水层从未按设计灵魂完成。主代理季级意图在
`src/v2/findSubtitleWorkerTask.ts` 的 `representativeEpisodeId()`（其注释自供抄自旧管线
executor.ts 的 `remainingTargets()`，`ORDER BY episode ASC LIMIT 1`）处被机械降解为单集指令，
worker 每 claim 一集、队列 retry 编舞缝合——系统驱动逻辑蹲在两个 agent 之间决定执行目标与
顺序，正是 v3 重生要消灭的模式。该缺口以"待核"标签存在于 2026-07-13 的设计记录中，穿过
绝对集数/B 层/旧管线退役/去 Jellyfin 四场战役无人翻牌，直至用户从纯语义层面（不看代码）
识破。

**方法论根因**（不是单点疏忽，是系统性盲区）：
1. **辐射分析=引用考古，非语义考古**。退役战役的"零活引用即安全"标准只能发现死代码，
   发现不了"活着但灵魂是旧的"代码。`representativeEpisodeId` 有引用、有测试、gates 全绿。
2. **验收面缺架构灵魂条款**。每 Task 的 gates（tsc/vitest/真站）验证行为正确性，从未对照
   北极星清单（"agent 像人判断，不敲计算器""主代理带全局意图派活""子代理粒度=季/批"）
   逐条质询新旧代码。verification-before-completion 只做了"代码级完成"，没做"设计级完成"。
3. **审查子代理从未以对抗人格出场**。所有实现子代理的自审+主控 diff 复核都在"这个改动
   对不对"层面，从没有一个"架构灵魂审计官"人格拿着设计文档去审"这个系统整体还符合
   它存在的理由吗"。serena codemap 全程可用，仅在退役删除前用过一次引用扫描。
4. **性能异象未触发架构质疑**。W0-5/T10 期间 job 被反复认领、一次一集的形态在日志里
   反复出现，被当作"正常的 retry 节奏"合理化，没有问"为什么季级任务会这样跑"。

**制度性修正（即刻生效，写入所有后续战役的执行纪律）**：
- R1 **架构灵魂验收**：每战役收官前，主控必须持北极星清单（见附录）对全部改动面逐条
  质询，产出书面对照表；任何"待核/TODO/暂时"标签不得跨战役存活——要么当场排期要么
  当场升级给用户。
- R2 **对抗审计人格**：每战役收官前，派≥1 个独立子代理，人格设定为"架构灵魂审计官"，
  输入=北极星清单+设计文档+改动 diff，任务=证伪"该系统仍配得上其设计宣言"，用 serena
  的符号级工具（find_referencing_symbols/codemap）做语义遍历而非 grep。
- R3 **旧世界血统申报**：任何注释/实现承认"抄自/同于旧管线"的存活代码，一律登记造册
  并逐个裁决（本 spec 第二部分即首次全仓执行）。
- R4 **性能异象=架构信号**：吞吐/节奏与设计预期不符时，先质疑架构再归因环境。

## 第一部分 · 胶水层修复 + 批量收割（战役主体）

**目标**：主代理意图端到端存活；一个 worker run 吃掉其任务范围内全部可完成目标。

1. **任务形状**：`FindSubtitleTask` 从单集字段改为批量目标——携带季级范围 + 该范围当前
   缺口的事实清单（集号+绝对号+路径），作为**事实**呈现（机械预清洗产物），不作为指令。
   多余机械字段（如单一 episode）废除。
2. **mapper 处决与降级**：`representativeEpisodeId()` 删除。`mapWorkerTaskToFindSubtitleTask`
   降级为纯信使：水合路径/上下文/绝对号表/TMDB 补面，**零目标选择、零顺序决策**。
3. **worker 收割语义**：skill（主控亲改）教导——进包后对清单内每个目标逐集验证归属、
   逐集安装；单集拿不准跳过该集不弃整包；finalize 从单决定改为批量报告
   `{installed:[], no_safe_match:[], retry_later:[]}`（schema 相应改造，coerce 容错沿用）。
4. **队列语义**：retry_later 表示"本季剩余部分"，completeDone 语义=本轮报告已入账；
   orchestrator 下轮按事实清单差额判断是否再派（判断留给 agent，差额是事实）。
5. **runs/dashboard 适配**：批量报告写 runs 行（每集一行或摘要行，实现期定夺并文档化）。
6. **验收**：真站（tunnel）同季多缺口场景——一次 claim 一轮 run 覆盖整季缺口的多数；
   R1/R2 纪律首次全流程执行。

## 第二部分 · 全仓旧世界残余语义考古（先于第一部分执行）

**目标**：回答用户的问题"还有多少老的弱智逻辑藏着"。范围=全部存活生产代码。

- 方法：R2 对抗审计人格子代理（serena 符号级遍历）+ 主控汇总裁决。重点嫌疑（已知线索，
  审计不限于此）：
  1. `findSubtitleWorkerTask.ts` 全文件（本次事故现场，胶水层另一半可能还有暗桩）；
  2. `sub_status='unavailable'+recheck_after` 退避梯（旧管线概念——裁决其作为事实层
     退避是否哲学兼容，还是变相确定性守门）；
  3. jobs 队列的 attempt/next_retry_at 指数退避语义（谁在决定"放弃"？agent 还是系统？）；
  4. 全仓 grep "旧管线|old pipeline|同 executor|抄自" 的存活注释逐条造册（R3 首执）；
  5. realign 触发链（exceedsSeasonTable 在 own-ingest 世界近死信号——已知，见第三部分）；
  6. orchestrator 工具面：是否还有"替 agent 做了判断"的工具行为（如 dispatch 工具内部
     的隐藏过滤）。
- 产出：残余清单 + 逐项裁决（处决/改造/哲学豁免+理由）+ 修复并入本战役或立项。

## 第三部分 · 债务三件（原 backlog"三小件"，用户令并入本 spec）

1. **realign 出生信号换代**：own-ingest 规范化使 mirror 永不超 TMDB 季表，

2. **orchestrate 心跳**：无变化世界里的低频兜底 pass（如每 24h），补"识别晚到/pending

3. **B-matrix 复跑**：orchestrator skill 强化（强制 layout 扫描）+ 本战役胶水层改造后，
   在 router 复跑 B 层真模型矩阵，重验零误触发与新批量派活行为。

## 附录 · 北极星清单（R1/R2 的质询基准，凝练自 2026-07-13 用户原始设计）

- agent 像人一样判断，不敲计算器；确定性检查绝不当守门人（事实盘点除外）
- 主代理=胶水层/理性中介：判断"什么需要做"，其意图必须原样抵达执行者
- 子代理粒度=季/批；合集包是最高效命中不是干扰；"一个工作流配齐三季"
- 机械层只产事实（活文档/清单/表格），永不产指令
- skill 修订权只在人+主控；拿不准就停车（park），错认比停车糟
- 零误触发是主代理存在的根本理由
