# 鉴权战役 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。
> 执行器=K3（一单一任务+强制汇报收尾）。铁律与 trailer 同债务波计划头。spec=docs/design/2026-07-17-auth-design.md（必读）。**队列末位（公开发布前置，用户判"还早"）。**

**Goal:** Sonarr 式单管理员：首启向导 + session cookie + API key，DASHBOARD_TOKEN 温和退役。

**现状坐标：** server.ts token 门散布各分支（`if (token && reqToken !== token)` 十余处——本战役收拢为统一前置）；settingsRepo（三键存储现成）；SSE 端点 query token 先例；web api client 统一入口（web/src/api/client.ts）；R2D-5 告警（dashboardTokenWarning.ts，本战役退役改文案）。

### A1: 凭据层
Create `src/dashboard/auth.ts`+test：scryptHash(password)→`盐:哈希`/verifyPassword（node:crypto scrypt+timingSafeEqual）/genApiKey(32hex)/SessionStore（内存 Map，token→expiresAt，30 天滚动，login 签发/verify/logout/失败节流 5次每分钟按 IP 内存计数）。纯模块零 IO。commit `feat(鉴权A1): 凭据与会话纯模块`。

### A2: 服务端统一门
Modify `src/dashboard/server.ts`+test：请求入口统一 `authGate(req)` 前置（在 rawPath 分支之前）：未初始化（settings 无 auth_username）→放行 /api/v2/auth/setup 与静态资源，其余 API 401 setup required；已初始化→cookie（httpOnly session）或 X-Api-Key 或 ?apikey=（SSE）或旧 DASHBOARD_TOKEN（等价 api key，兼容）验过才进分支——**原散布的十余处 token 门整体删除**（单一实现防漂移）。新分支：POST /api/v2/auth/setup（一次性 403 语义）/login（签 cookie）/logout。dashboardTokenWarning 改为"未初始化提示 setup"与"建议从 token 迁移"两文案。测试：未初始化矩阵/401 矩阵/四通道各通/旧 token 兼容/节流。commit `feat(鉴权A2): 统一鉴权门`。

### A3: 前端
Create `web/src/auth/`（SetupPage/LoginPage/useAuth——client 统一 401→跳 login，setup required→跳 setup；hash 路由加 #/setup #/login，Shell 外层判定）；Settings 加 Security 区（改密码需旧密码=POST /api/v2/auth/password；重生成 API key 显尾 4 位+复制）。登录页标题 serif（DESIGN.md 仪式感唯一豁免处）。i18n 双语。测试：未登录重定向/登录流/改密码流。commit `feat(鉴权A3): setup/login/Security 区`。

### A4: 收官
双侧全绿；SSE 带 apikey 真机验证；R2 对抗复审一轮（重点：门有没有洞——静态资源含 index.html 放行是否泄漏信息、setup 竞态）；README 部署节更新（含反代 TLS 建议）；登记册 R2D-5/R2D-2 归档项闭环落册。
