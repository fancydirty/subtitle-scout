## 跨 spec 的通用纪律

### 模型面 schema 必须容错

六轮血案的教训（`src/agent/identityTools.ts:11-23` 有完整记录）：`write_identified_media` 的 `season/episode` 用了 `z.number().int().nullable()`，只收 JSON null 和真数字，而真模型的六种发法五种被拒（省略键 / `"None"` / `"null"` / `""` / 字符串数字）。agent **想调工具却调不进去**，把失败写进 finalize 的 reason。我把这个现象误判为"agent 不听话"，往 skill 里加了三轮措辞，全打在空处。

**凡新增模型面字段，必须复用 `src/agent/coerce.ts` 的 helper**（`coercibleNullableInt` / `nullableJsonTolerant` / `nullableBooleanTolerant` / `tolerantArray`），不要新造更窄的门。

### 不向模型索要它拿不到的数据

同一缺陷类的第二例：`write_identified_media` 曾要求绝对 `path`，而 prompt 出于沙盒纪律**刻意只给相对目录段和 basename**。模型没有这个信息，只能编——14 次调用 13 次是 `../../../../..` 拼接幻觉。改成模型报 `file` 名、代码用 `resolveTargetPath` 解析真实路径后解决。

**新增字段前先问：prompt 里真的给了模型这个信息吗？**

### 措辞不是机制

调研结论（Anthropic Agent Skills / prompt-at-scale）：

> CAPS, bold, "IMPORTANT," "MUST," "NEVER." These are retry logic for prose. If a step needs emphasis to be reliable, it needs to be code.

需要靠强调才可靠的步骤，本身就该是代码约束。skill 保持精简 + progressive disclosure（`SKILL.md` 只留索引，大块内容拆独立文档按需 `read_doc`）。**测试不要锚定强调性措辞**——锁住它们等于把错误做法固化成契约。

### 调研类子代理必须边查边写文件

公司主站 LLM API 会断线。实施类子代理断了无妨（已写的代码还在，接续派即可）；**调研类子代理断了则成果全失**。所以调研任务一律要求**增量写入文件**（`docs/superpowers/research/`），断线后可从残留文件判断进度，决定"信息够了"还是"接续派"。

### 不许编造根因

已发生过一次：我把评估耗时异常归因为"TMDB 限流"，日志里零证据（真因是 agent 被 schema 拒后反复重试打转）。**没有证据的因果推断一律不写进结论。**
