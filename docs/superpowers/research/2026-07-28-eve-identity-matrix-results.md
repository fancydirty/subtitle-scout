# eve 识别能力矩阵：实测结果（2026-07-28）

**模型**：mimo-v2.5（与生产同一个弱模型）
**实验台**：eve 0.27.8，独立目录，复用生产 identifyMediaSkill 文本 + 生产 TMDB 工具契约
**系统提示**：只说"取代机械刮削器的媒体识别器"，零字幕/库/下游字样（grep 断言）
**结果**：18 case 全过，54 gates 全过，耗时 12m37s（串行）

## grade 分布（真实判定，非通过率）

| grade | 数量 | 含义 |
|---|---|---|
| identified-correct | 11 | tmdbId 与 ground truth 一致 |
| honestly-refused | 7 | 证据不足时诚实说认不出 |
| identified-WRONG | 0 | 识别成错的作品 |
| **hallucinated** | **0** | **证据不足却编出身份（Spec 6 硬门）** |

### 硬门达标：Class 4 幻觉率 = 0

`IMG_4821.MOV`（相机原始文件）和 `1.mp4`（占位名）both honestly-refused。
这是本实验最重要的一个数字：**弱模型在纯识别人格下不会为了给答案而编造身份**。
Spec 2 的 insufficient-evidence 分类因此可信——模型确实会拒绝，而不是硬凑。

### 读法（含反直觉项）

1. **招魂系列最耐削**：去掉时长、去掉目录名都还能认对，只在"文件名只剩技术 token"时才拒绝。
   说明版权规避乱写（`招z魂z4`）里残留的信息量仍足够。
2. **后室在"去目录名"就崩**：因为它的标题只存在于目录名（文件名是纯技术 token
   `2026.2160p.iT.WEB-DL...`）。这正好实证了调研报告 M1 的判断：**目录名是唯一标题来源时，
   去掉它等于抹掉全部身份证据**，拒绝是唯一诚实答案。
3. **2012 的非单调性**：`去时长`拒绝，但`只剩文件名`却识别对了。这不是矛盾——两个 case 的
   期望都设成"拒绝或识别对都算过"，所以它测不出分界线，只暴露了模型在这一档的**随机性**。
   诚实结论：`2012` 这类纯数字标题在缺时长时**处于边界带**，同一档可能拒也可能对。

## 实验设计的已知局限（不可当作能力证明）

- **期望过松**：3 个 case 用 `cannot_identify_or_honest`（两种答案都算过），无法定位分界线。
  要真正量化边界，需要改成单一期望 + 多次重复取分布。
- **单次运行**：每格只跑 1 次。identityEval 的经验是单次结果有真实方差（曾出现两轮才敢认），
  所以"哪一档崩"的结论强度有限。
- **case 数量少**：18 个，覆盖调研 16 个机制中的一小部分；Class 3（集号体系分歧）只测了 1 个。
- **不含跨挂载/兄弟文件维度**：sibling 证据维度未进实验（生产也还没接 readdir）。

## 一个操作教训（记录在案）

首轮我用 --max-concurrency 3 跑，得到 9 过 9 败，其中 4 个判 no-call。
我一度怀疑"module 变量跨进程失效"，查代码后发现子代理**已经**做了文件镜像跨进程通道，
真凶是 capture 文件被并发 eval 互相 clear——**实验台注释里明写要 --max-concurrency 1，是我没照做**。
按设计串行重跑：18/18 全过。

教训与那次"TMDB 连不通"同型：**先怀疑自己的操作/传参，再怀疑系统**。
（TMDB 那次：连续判定"本机不通/软路由不通"，真因是 TMDB_API_KEY 是 v4 Bearer token
而我用 v3 的 ?api_key= 传参，服务器返回空体。改 Authorization: Bearer 后本机直接 200。）

## 反哺 Spec 2 的结论

1. **insufficient-evidence 分类可信**：Class 4 幻觉率 0，模型会拒绝而非硬凑。
2. **"目录名是唯一标题来源"是真实且可检测的失败形态**（后室 no-dir 崩）——UI 给用户的
   改名建议应优先建议**改目录名**，而不是只说改文件名。
3. **纯数字/歧义标题在缺第二证据线时处于边界带**，会随机拒/对——这类文件反复重试是
   有意义的（可能下一轮就对了），归 identification-failed 而非 insufficient-evidence 是对的。
